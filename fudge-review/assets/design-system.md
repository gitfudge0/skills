# Review with the shared HTML plan UI

The review renderer uses the actual HTML plan runtime. This is exact UI reuse: numbered nested claim rows, parent rows, contents rail, comment buttons, and the floating comment/response UI. Review adapts the recorded content only. Do not create a second skin, duplicate tokens, override shared CSS, replace the tree with disclosures, or remove the runtime's comment UI.

## Authoritative assets

Resolve the package root as described in the review root guide. In the source checkout, canonical assets are `plan/runtime/htmlplan.css`, `htmlplan.js`, and `pack.mjs`. In an installed review package or another root that includes review, they are under package-root `references/roots/plan/runtime/`. The review root's `plan` dependency bundles them; review does not own or fork them.

- `example-review.src.html` is the editable review template. It links the canonical checkout runtime using `../../plan/runtime/` and has no custom styles or scripts.
- `example-review.html` is generated by the shared `pack.mjs`, which inlines that runtime. It is the portable offline example, not an independently maintained renderer.

Use the shared runtime's default type, reading width, spacing, paper colors, tags, hover states and comment surfaces. Read its CSS for exact tokens rather than maintaining a review-specific palette here. For copied or installed unpacked source, adjust only the runtime link paths to their resolved location. The shared packer can also resolve the canonical CSS/JS beside itself if checkout-relative template links are unavailable.

Generate the bundled example from the checkout:

```sh
node plan/runtime/pack.mjs fudge-review/assets/example-review.src.html -o fudge-review/assets/example-review.html
```

Generate a report with an installed package's runtime, from its package root:

```sh
node references/roots/plan/runtime/pack.mjs /absolute/review/output/review.src.html -o /absolute/review/output/review.html
```

Copy and edit source at the caller-resolved artifact destination. Pack that report; do not overwrite the bundled example for a real review.

## Content organization

Header: review title in `h1`, complete verdict immediately below, then metadata with the shared `meta` class. The verdict and its counts come from recorded open author findings, independently of annotations. Preserve subject-aware readiness and CI qualifications.

Use one `doc-plan open="0"`. Each top-level `doc-claim` is an author finding, organized by affected behavior. Its first `p` shows stable R ID, exact symptom title, severity/status text, and recorded `SUSPECTED` / `pre-existing` exceptions. Set `id="R<n>"` on the claim; runtime-generated tree numbers supplement rather than replace these IDs. Use canonical `pill` classes (`red`, `amber`, neutral, `green`) without review-specific fill/outline overrides.

Colocate recorded Fix and optional Impact/Rule/status reason in a `doc-note`. A level-2 child states the recorded Cause and displays the exact `evidence` in one `doc-code lang="text"` exhibit, using the shared inert `script type="text/plain"` source wrapper. A level-3 child shows Where last, with the main location in `at` and all recorded locations in a plain-text exhibit. Recorded text is sufficient; do not manufacture code excerpts or trace steps. Use a code excerpt only when already present in approved evidence. No `src`, `ref`, source-reading call trees, or fresh repository reads during rendering.

The shared runtime opens descendants when a claim is opened. Its keyboard behavior, parent rows, TOC and comment response interaction remain unchanged. Do not add review-specific expanders, filters, stats, severity sections, flat field lists, or theme/print scripts. The canonical default is compact sans with near-black/gold colors, a built-in persisted Light mode / Dark mode control, and a white/gold print palette. Open parent rows stay in document flow.

On re-review, keep each ID and render only the recorded delta. Put fixed / still open / new labels inline on the finding row. New is a round label derived from `round_found`; it does not replace status `open`. Keep no-longer-applies and its reason distinct; omit dropped findings. Do not regroup the behavior tree into separate status sections.

Final auxiliary claims use `aux="team"` with “For the team” and `aux="method"` with “Method and coverage”. Arbitrary auxiliary labels are supported by the shared runtime and receive its auxiliary marker. Omit Team when empty. Preserve stable team IDs and source method coverage. If there are no author findings, state that before the tree; if there are no auxiliary claims either, omit an empty tree.

## Annotations and evidence

Keep the shared comment buttons and floating comment/response UI. Explain in Method that copied responses are feedback data. They do not mutate `findings.json`, approve a review or change triage. Re-verify feedback before changing recorded findings. Do not add `doc-ask` build decisions, editable schemas or mock controls.

`findings.json` remains the sole findings source; `method.md` supplies coverage. Preserve evidence verbatim as inert source text. Escape prose and attributes; do not HTML-encode raw text inside `script type="text/plain"`. For evidence containing a closing script tag, use the runtime-supported `textarea class="src"` wrapper with HTML-escaped content so the characters remain intact. Keep uncertainty and what would settle it. No schema changes or new claims in the render pass. Example names and evidence are fictional and must be labelled as such.

## Verification

Run the actual shared packer and inspect errors and warnings. Planning-only warnings can legitimately flag review titles and inline tags, more than five findings, missing `aux="scope"`, or `doc-note` content not counted as a planning exhibit. Report them; do not rewrite approved review text or relabel Method to silence them. Fix actual packing errors.

Compare source/packed review text and stable IDs. Check the packed CSS/JS match the canonical runtime, that no external runtime links remain, and that template JavaScript has no custom renderer. Check an isolated installed package can pack its copied source without the checkout. Regenerate the packed example whenever its source or shared runtime changes.
